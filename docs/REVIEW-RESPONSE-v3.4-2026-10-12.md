## 一、真实时间戳的时区语义（复评第 1 条 · 已修）

| 要素 | 内容 |
|---|---|
| ① 问题 | 证据里 `capturedAt` 为不带时区的 `2026-10-12 08:09:42`，而 `sourceTrace/generatedAt` 用带 `Z` 的 UTC；freshness 把前者按 `+08:00` 解读，于是**刚生成的案例被标成约 480 分钟前**——存在 **8 小时歧义**。 |
| ② 根因（**我方**） | `cli.ts` 在线路径用 `new Date().toISOString()` 取**UTC 墙钟**，又 `.slice()` 掉 `Z`，再被 `freshness` 按 `+08:00` 解读 → 凭空差 8 小时。**根因不在服务端，在我生成时刻的方式**。 |
| ③ 修改 | ① 新增 `freshness.ts::localIsoNow()`，在线路径改用**本地带偏移**时刻（`2026-10-12T21:23:55+08:00`）；② `parseCapturedAt(capturedAt, { observedAt })` 新增**推断**能力：无时区时，以「按本地偏移解读」与「按 UTC 解读」二者中**更接近本地观测时刻**者为准，并回写差值；③ 无 `observedAt` 时**退回「假定 +08:00」并如实标注**（不再默认冒充精确）；④ `freshnessOf` 结果新增 `timezoneBasis` / `timezone` / `observedDeltaMinutes`，JSON 另出 `observedAt`。 |
| ④ 实际入口 | `cli.ts::loadFromOnline`（写 `observedAt`）→ `freshnessReport()` / 文本渲染 → JSON `freshness.{observedAt, sources.*.timezoneBasis}` |
| ⑤ 通过日志 | `tests/v34-review-regression.test.ts` **11 条全绿**（含「服务端为 UTC 时能识别」「服务端为本地时区时也识别」「无观测时刻时退回假定」「带时区时 explicit」「不再算成 8 小时前」「localIsoNow 带偏移」）；四例真实案例重跑后 `status=fresh age=0min basis=explicit tz=+08:00`。 |
| ⑥ 适用范围 | 全部新鲜度判定与证据。**离线快照**因非「此刻取到」，不填 `observedAt`，仍按假定处理并在 note 写明。 |

> 复评要求的两个选项——「原始回执保留明确时区」**或**「同时记录服务端数据时间与本地请求时间」——本轮**两者都做了**：
> 时间串带显式偏移，且 JSON 同时给出 `capturedAt`（服务端/取数时刻）与 `observedAt`（本地观测时刻）。
