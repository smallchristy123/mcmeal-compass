## 二、根因（我方实现）

```ts
// 修前（src/matching.ts）
return hasComposition ? 'A' : 'B';
```

`hasComposition` 表示「该餐品是否有官方组成信息」；**单品没有组成，调用处恒传 `false`**，
故 **A 对单品永远不可达**——而 README 写着「A：官方单品」，属**文档与实现背离**。

## 三、甲案处置（主君裁定）

| 要素 | 内容 |
|---|---|
| ① 语义 | **A** ＝ 官方单品**精确直配**（`code-mapping` / `exact-name`）、营养**完整**、**不含推断**；**B** ＝ 组合求和，或含推断/别名/变体/份量匹配；**C** ＝ 部分可知；**D** ＝ 无可用信息 |
| ② 修改 | `matching.ts::assignConfidence()` 判据改写；第二参数由 `boolean` 扩展为 `boolean \| { hasComposition?, method?, risky? }`——**沿用布尔者（组件级匹配）行为不变**；`analyze.ts::analyzeSingle()` 传入 `method` 与 `risky` |
| ③ 实际入口 | `matcher.match()` → `analyzeSingle()` → `AnalyzedItem.confidence` → 展示层（`A 官方单品` 标签）与推荐池（A/B 才入完整推荐） |
| ④ 通过日志 | 新增 `tests/v36-a-level.test.ts` **6 条**：① 精确直配完整无推断 ⇒ A；② 含推断（risky 别名）**不升 A**；③ 精确但不完整 ⇒ C；④ 未命中 ⇒ D；⑤ 判据表（含 `code-mapping` 亦算精确、`hasComposition` 保留旧行为）；⑥ **可达性实测**——快照内 A 级数 > 0 **且 A 级全为单品**、套餐不得为 A。`npm run gate` **312 用例全绿** |
| ⑤ 适用范围 | 单品与套餐的可信度分层。**组合求和仍为 B**（不因本改动升 A）；含推断者仍为 B |
