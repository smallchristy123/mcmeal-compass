## 二、逐条怎么做、怎么验

### P0-1 可复现（提交 `635c0ad`）
```bash
npm run verify:fixtures   # 校验 6 个文件的 SHA-256 与条数，不一致即非 0 退出
npm run capture -- 3450024 --details 20   # 采集只落 work/captures/，**不碰** fixtures/
npm run gate              # 夹具 → 测试 → 类型 → 离线可跑
```
- 快照：`fixtures/baseline-20261010-3450024/`（含 `manifest.json`：来源、每文件 SHA-256、条数统计）
- `capture` 若目标路径以 `fixtures` 开头**直接拒绝执行**
- **额外发现并修掉一个隐患**：新增 `.gitattributes`，令 `fixtures/**` 按二进制存取。
  否则 Windows `core.autocrlf=true` 会在检出时把 LF 换成 CRLF，**哈希校验在别的机器上必然失败**。
- 自查：`git show HEAD:fixtures/.../query-meals.raw.txt` 的字节哈希 = manifest 记录值（已逐一核对）

### P0-2 协议（提交 `e272b32`）
```bash
npm test -- tests/protocol.test.ts    # 11 条：JSON / SSE / 401·429·5xx / 版本不匹配 / modern 形态
```
- 响应双路径（JSON + SSE，跳过非 JSON 心跳）；id 不匹配 → `BAD_RESPONSE`（防串包）
- legacy：`initialize` → `notifications/initialized` → 业务请求，并**回传** `Mcp-Session-Id`
- modern（2026-07-28 起）：不发握手，每请求带 `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name` + `_meta`
- `-32022` → `UNSUPPORTED_PROTOCOL_VERSION`，并带出服务端支持的版本
- README 新增「协议兼容」节，**只声明已验证范围**：legacy 对 `mcp.mcd.cn` 实测可用；modern 仅本地 fake server 验证过
