## 为什么必须人工，不能由程序自证

程序能算的是「名字像不像」，算不出「是不是同一个东西」。
本项目最重要的两条铁律（**份量/口味不同即不同物**、**组合品不得映射到单品营养**）恰恰是**语义判断**——
只能由人拍板。**用机器给自己判卷，等于把"谁是同一物"这个前提自己定了，然后宣称自己判得准。**

## 流程

```bash
npm run review:samples                      # 1) 生成分层抽样表（≥30 条）
# 2) 人工逐条填「判定」列：same / diff / unknown
npm run review:score -- <csv 路径>           # 3) 汇总精度与误配清单
```

## 抽样分层（35 条）

| 分层 | 条数 | 为什么要抽它 |
|---|---|---|
| 单品·精确命中 | 8 | 主体正确性 |
| 单品·别名命中（含 `risky` 推断） | 4 | **推断成分**是否越界（如「麦辣鸡翅」按 2 块计） |
| 套餐·展开求和 | 8 | 组合品拆分是否正确（四件套 ≠ 单品） |
| 饮料（含份量歧义） | 4 | 份量单位易错区 |
| 份量歧义（待用户指定） | 3 | 是否**没有**替用户猜 |
| 口味歧义（待用户指定） | 3 | 同上，口味维度 |
| 新品未收录（营养表滞后） | 4 | 是否**没有**拿近似品顶替 |
| 非食品周边（玩具/贴纸） | 1 | 是否**没有**把周边当食物 |

> 「非食品」层实际只有 1 条——该门店菜单里只有 1 个非食品项，**不是抽样失败**。

## 判定口径

| 判定 | 含义 | 计入 |
|---|---|---|
| `same` | 机器给的营养来源与菜单项**确为同一物**（份量、口味、规格都一致） | 分子 |
| `diff` | **不是同一物**（四件套配成单品、口味不同、份量不同…） | 分母，并进误配清单 |
| `unknown` | 官方信息不足，无法判断 | **单列**，既不算对也不算错 |
| 留空 | 未审 | **不算通过**（脚本会明确提示「未填不算通过」） |

## 审核完成后要产出

1. **按分层公开精确率**（脚本自动汇总）；
2. **误配清单**：每条误配必须落到 `src/aliases.ts` 的「禁配」条目，或改匹配规则；
3. **已知错误一律不得进入 A/B 级**（计划书 §11.2 硬要求）；
4. 把结果回填到本文件与 `docs/MATCHING_NOTES.md`。
