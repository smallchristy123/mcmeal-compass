## 二、P1 · 交付包根目录脚本无法按指南运行

| 要素 | 内容 |
|---|---|
| ① 反例 | 复评按指南在包根目录执行 `node independent-online-verify.mjs`，**失败**——脚本内为静态相对导入 `../../src/*.ts`，在包根解析后指向**包外不存在的源码** |
| ② 修改 | 源码根改为**动态解析**：依次探测 `SOURCE_ROOT` → `<包根>/mcmeal-compass/src` → `<脚本>/../../src`（仓库布局）→ `<脚本>/../src` → `<cwd>/mcmeal-compass/src`，命中即用 `pathToFileURL` + `await import()` 载入；全部落空时给出**明确指引**（先解压内核包并在其中 `npm install`）。输出目录默认改为 `./independent-output`（可用 `INDEPENDENT_OUT` 覆盖） |
| ③ 实际入口 | 脚本自身（`scripts/independent-online-verify.mjs`，随包发布至**包根**） |
| ④ 通过日志 | **仓库布局**：`node scripts/independent-online-verify.mjs` → 运行成功，自检 `P1-source-root-resolved = PASS`；**交付包布局**：解包 → 解内核 → `npm install` → **在包根** `node independent-online-verify.mjs` → 运行成功（见包内 `package-root-run.log`） |
| ⑤ 适用范围 | 脚本的两种分发形态（仓库 `scripts/`、交付包根目录）均**开箱可跑** |

## 三、P2 · `responseBytes` 记的是字符数，不是 UTF-8 字节数

| 要素 | 内容 |
|---|---|
| ① 反例 | 原实现 `responseBytes: raw.length` —— JS 字符串 `length` 是**UTF-16 码元数**；含中文时与 UTF-8 字节数不符。复评指出 **29 条全部存在口径差异** |
| ② 修改 | 改为 `Buffer.byteLength(raw, 'utf8')`；另**新增 `responseChars`** 并保留二者，使口径差一目了然 |
| ③ 实际入口 | 逐调用记录（`calls[].responseBytes` / `responseChars`），以及自检项 |
| ④ 通过日志 | 自检 **`P2-responseBytes-is-utf8-bytes` = PASS**（逐条等于原始响应文件的 UTF-8 字节数）；**`P2-bytes-differ-from-chars-on-cjk` = PASS（29/29 条二者不同）**；样例：`query-meals` 字符 18,423 / 字节 20,903；`list-nutrition-foods` 6,666 / 8,714 |
| ⑤ 适用范围 | 全部调用记录与归档；哈希口径不变（`createHash().update(str)` 本就按 UTF-8 计算，无需改） |
